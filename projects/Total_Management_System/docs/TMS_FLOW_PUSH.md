### ① 기기 하나만 알림을 받고 있었다 ← 가장 큰 원인

`api/push/subscribe` 가 **사용자당 토큰 1개** 정책이었다.

```ts
// 삭제된 코드
await db.from('push_subscriptions').delete().eq('user_id', user.id).neq('token', token);
```

**TMS를 새 기기에서 열 때마다 다른 기기의 토큰이 삭제됐다.**
- PC에서 열면 → 모바일 토큰 삭제 → 모바일 알림 끊김
- 모바일에서 열면 → PC 토큰 삭제 → PC 알림 끊김

실측(2026-09-15): `push_subscriptions` **1행**. 원래 의도는 "같은 기기가 캐시 비움·재구독으로 토큰을 중복 누적"을 막는 것이었는데, 그건 **user 가 아니라 device 단위**로 막아야 했다.

같은 기기의 옛 토큰만 교체하고 다른 기기는 건드리지 않는다.
`api/push/cleanup-others`(다른 기기 토큰 일괄 삭제)는 같은 사고를 재발시키므로 **삭제**했다.

### ② 아임웹 주문이 최대 13시간 늦게 들어왔다

폴백 크론이 `0 0 * * *`(= **한국 09:00, 하루 1회**)였다. 실측 지연:

| 주문 시각(UTC) | TMS 저장 | 지연 |
|---|---|---|
| 09-05 14:25 | 09-06 00:00 | **9시간 35분** |
| 08-21 11:01 | 08-22 00:01 | **13시간 0분** |

**수정**: `*/15 * * * *` (15분). 실시간 경로는 여전히 **웹훅**(`ORDER_CREATE`)이고, 크론은 웹훅이 실패했을 때의 안전망이다.

> ⚠️ 웹훅 경로는 아직 **실주문으로 검증되지 않았다.** 마지막 실주문이 09-05인데 웹훅 연결은 09-14였다.
> 알려진 위험: 웹훅 재조회가 v2 `getOrder` 를 쓰는데 새 OpenAPI 주문번호가 v2에서 조회되는지 미확인([imweb_api_limits] 메모).
> 그래서 ③ 실패 알림과 15분 크론을 함께 넣었다.

### ③ 웹훅 동기화 실패가 조용히 묻혔다

웹훅은 왔는데 주문 조회/저장이 실패하면 `process_error` 만 남기고 끝이었다 → "주문이 안 들어온다"를 며칠 뒤에 알게 된다.
**수정**: 실패 시 즉시 사장님 푸시(`⚠️ 아임웹 주문 동기화 실패`). 15분 크론이 자동 재시도한다.

## 발송 구조

```
고객 행동 / 상태 변화
   ↓
sendNotification(template)          ← lib/notification/make-webhook.ts
   ├─ ① 사장님 푸시 : PUSH_CONFIG[template] 있으면 발송   ← 알림톡 로직보다 먼저(early-return 영향 없음)
   └─ ② 고객 알림톡 : Make 웹훅 → 솔라피
   ↓
sendPushToAll()                     ← lib/firebase/send-push.ts
   ├─ push_subscriptions 전 행(=등록된 모든 기기) 조회
   ├─ FCM sendEach 배치 1회 발송     ← 순차 send 루프의 지연·부분누락 제거
   ├─ 만료/무효 토큰만 자동 삭제      (not-registered / invalid-registration)
   └─ push_notifications 저장         ← TMS 탭이 열려 있으면 Realtime 으로 소리
```

### 🚨 손대면 안 되는 것

- **푸시는 무조건 발송** — on/off 게이팅 없음(2026-08-01). 고객 접수를 놓치면 안 되므로 어떤 설정으로도 차단하지 않는다
- **`after(deliverPush)` 로 완주 보장** — fire-and-forget `import().then()` 은 Vercel이 응답 후 함수를 죽여서 접수 3종 알림이 오락가락하던 근본원인이었다
- **`sendPushToAll` 은 user 필터 없이 전 토큰 발송** — 기기별 필터를 넣으면 다시 한 대만 받게 된다

## 알림이 안 올 때 — 확인 순서

1. **설정 → 알림 → 「알림 받는 기기」** 에 그 기기가 있는가
   - 없으면: 그 기기에서 TMS를 열고 **알림 권한 허용** → 자동 등록
   - PC·휴대폰 **각각** 한 번씩 열어야 둘 다 등록된다
2. **아이폰이면 홈 화면에 추가(PWA)** 했는가 — iOS는 사파리 탭에서 웹푸시가 오지 않는다. 설정 화면에 자동 안내가 뜬다
3. 브라우저 알림 권한이 **차단**돼 있지 않은가 (주소창 자물쇠 → 알림)
4. **설정 → 알림 → 푸시 테스트** 로 실제 발송 확인
5. 그래도 안 오면 `push_notifications` 테이블에 행이 쌓였는지 확인
   - 행이 있는데 푸시만 안 옴 = 토큰/권한 문제 (1~3번)
   - 행도 없음 = 발송 코드가 호출되지 않음 (서버 로그 `[FCM]` 확인)

> 💡 SW 캐시 때문에 안 바뀌는 경우: 크롬 개발자도구 → Application → Service Workers → **Unregister** 후 새로고침 ([reference_tms_deploy_gotchas])
