# 직접 전달 완료 알림톡 등록안 (2026-11-21)

> 흐름: [TMS_FLOW_REPAIR.md](TMS_FLOW_REPAIR.md) 2026-11-21 절
> 언제: 택배로 보낼 복원수리 건을 송장 없이 손으로 건넨 뒤, 복원수리 상세 → `다른 처리 방법` → `직접 수령 (매장 전달)` 을 눌렀을 때
> 왜: 수리내역서 링크는 출고 알림톡(`as_shipped`)에만 있어, 택배를 안 타면 고객에게 갈 길이 없었다

## 가동 순서
1. 솔라피에 템플릿 등록 · 검수 신청 (아래 본문 · 버튼 · 카테고리 · 검수 메모 · 배너)
2. 승인되면 Make `02 복원수리 (접수·상태변경·후기)` 에 분기 1개 추가 (아래 「Make 분기」)
3. 시험 발송 1회 → 끝. TMS 쪽은 이미 신호를 보내고 있어 따로 켤 것이 없다

**분기를 만들기 전까지**: TMS 는 `as_handed_over` 신호를 보내지만 Make 가 받아서 아무것도 하지 않는다
(2026-11-21 확인 — 이 시나리오의 분기 14개는 전부 `template` 이 정확히 같을 때만 동작하고 "그 밖" 분기가 없다).

🚨 솔라피 변수명 = TMS 가 보내는 키 그대로 (`name` · `as_id` · `as_uid` · `qty`). 바꾸면 빈칸으로 나간다.

## 템플릿 — `as_handed_over` · 이름 `TMS-직접전달완료`

- **카테고리**: 서비스이용 > 처리완료 (004003) · **이미지형**
- **배너** (800×400 · 배경 #F9F9F9 · 굵은 한글 2줄): **복원 완료된 가위 / 직접 전달했어요** + 오른쪽 3D 아이콘
- **아이콘 내용**(Meshy · 공통 스타일은 `알림톡_아이콘\Meshy프롬프트_8종.md` 그대로): 두 손이 가위 한 자루를 건네는 모습, 가위 손잡이에 작은 꼬리표

**본문**
```
#{name}님, 안녕하세요
복원을 마친 가위를 직접 전달해 드렸습니다

✅ 전달 내역
• 접수번호 : #{as_id}
• 가위 : #{qty}자루

가위별 작업 내용은 수리내역서에서 확인하실 수 있습니다
```

**버튼**: 웹링크 [수리내역 조회] (기존 「복원수리 출고」와 같은 이름)
→ `https://page.mamoru.kr/projects/as/page_as_report.html?uid=#{as_uid}`

**검수 요청 메모**
```
광고·홍보가 아닌 정보성 메시지입니다

[발송 대상] 가위 복원수리를 직접 신청하고 가위를 맡긴 고객 본인에게, 수리가 끝난 가위를 직접 전달한 시점에 1회 발송합니다 (전체 발송 아님)
[발송 목적] 맡긴 가위가 전달 완료되었음을 알리고, 가위별 수리 내용을 확인할 수 있는 수리내역서를 안내합니다
[버튼] 「수리내역 조회」는 해당 고객의 수리내역서 페이지로만 이동합니다 (구매·이벤트 페이지 아님)
[변수] name=고객명 / as_id=접수번호 / qty=맡긴 가위 수 / as_uid=수리내역서 조회용 접수번호
```

## Make 분기 — 시나리오 `02 복원수리 (접수·상태변경·후기)` (id 9837029)

- 분기 이름: `직접전달_완료`
- 조건: `template` = `as_handed_over` (text: equal)
- 솔라피 알림톡 변수: `#{name}`→`name` · `#{as_id}`→`as_id` · `#{qty}`→`qty` · 버튼 `#{as_uid}`→`as_uid`
  (웹훅이 이미 이 네 값을 받고 있어 웹훅 구조를 다시 읽힐 필요 없음)
- templateId: 검수 승인 후 입력

## 후기 요청과의 순서
- 전달 안내(이 알림톡)는 버튼을 누른 즉시, 후기 요청(`as_review_request`)은 **3시간 뒤** 나간다 (밤 9시~아침 9시는 건너뛰고 다음 회차).
- 방문 건(「고객 전달 완료」)과 같은 규칙 — `api/cron/repair-visit-remind` [3].
