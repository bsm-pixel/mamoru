| 변경 | 사장님 화면에서 보이는 차이 |
|------|---------------------------|
| **출장 확정 알림톡** | 이전: 확정 후 카톡 알림톡이 **문자(SMS)** 로 떨어짐 → 이후: **카톡 알림톡 정상** 발송 + 본문 방문 주소·일정 변경 버튼 정상 |

| **수동 일정 변경 알림톡** | 이전: 확정 상태에서 시간만 바꿔도 고객에게 변경 알림톡 미발송 (Make 웹훅 자체 호출 안 됨) → 이후: **`field_rescheduled` 알림톡 정상** 발송 (Make `출장_일정변경(관리자변경)` 모듈로 라우팅) |
| **고객 일정변경 요청 페이지** | 이전: 변경 알림톡 → "일정확인/변경" 버튼 → 일정 변경 + 요청하기 → **"예약 정보를 찾을 수 없습니다" 404** → 이후: **정상 처리** (`reschedule_requested` 상태로 전환 + 관리자 이메일/푸시 알림 + 캘린더 ⏳ 접두어 업데이트) |
| **출장 취소 알림톡** | 이전: 카톡 알림톡 본문에 `#{visit_date}` 등 **원본 변수**가 그대로 떠 있음 → 이후: 실제 일정·주소가 정상으로 채워져 발송 |

> 어느 순서로 처리하든 (사장님이 미리 잔금 받고 변경 / 고객이 셀프로 변경 요청 / 취소 등) 알림톡이 항상 올바르게 발송되는 흐름으로 정리됨.

## 📌 수동 일정 확정/변경 — 사용 가이드 (직원/사장님)

**언제 사용?** 고객이 이미 접수했지만 DM/유선으로 별도 협의해서 새 날짜·시간이 잡혔을 때

### 단계별 사용법

#### 1️⃣ 상담 상세 열기
1. 사이드바 → **상담관리** 클릭
2. 좌측 list에서 해당 고객 건 클릭 → 우측 패널 표시

#### 2️⃣ 수동 일정 확정 버튼 클릭
- 매장방문 / 출장요청 모두 사용 가능
- 활성 상태 (신규접수, 시간제안중, 재요청, 확정 등)에서 노출
- ⛔ 톡상담, 진행중, 완료, 취소 상태에는 노출 안 됨

#### 3️⃣ 모달에서 입력
| 필드 | 입력 |
|------|-----|
| 현재 상태 | 자동 표시 (예: "출장요청 · 시간 제안중") |
| 날짜 | 협의된 날짜 선택 (`<input type="date">`) |
| 시간 | 협의된 시간 선택 (`<input type="time">`) |
| 메모 | 선택 — 자유 입력 (예: "DM 협의", "유선 협의") |

> 💡 사장님 룰: 막힌 날짜(휴무 등록한 날)에도 자유롭게 등록 가능

#### 4️⃣ "확정 처리" 버튼 → 자동 후속 작업
시스템이 자동으로:
1. ✅ 상태 → **확정(confirmed)**
2. ✅ Google Calendar 갱신 (이전 이벤트 정리 + 새 이벤트 생성)
3. ✅ 고객에게 **확정 알림톡 자동 발송** (field_confirmed / confirmed 템플릿)
4. ✅ 이력 기록 (상태 전이 + 메모)

#### ⚠️ 이미 확정된 건의 일정 변경
- 상태가 이미 confirmed인 경우 → 모달에 **노란 안내** 표시
- 일정만 변경됨 → **변경 알림톡 재발송**

## 9. 달력 관리 (`/consultations/calendar`) — 078 신설 / 096 고도화 (2026-05-27)

### 화면 구성
- **상단 안내 카드**: 막힘은 **모든 고객 셀프예약(매장/출장/톡 + 복원수리 직접방문)**에 적용 / 사장님 측은 항상 유동
- **영업 기본시간 카드** (096): 시작~종료 시 입력 + 저장. 모든 셀프예약 폼의 가용 슬롯 범위에 반영 (설정 탭에서 이전됨 — SSOT 단일화)
- **정기 휴무 요일 토글 카드** (월~일 7개 버튼): 클릭으로 즉시 토글, 매주 반복 적용
- **4개월 달력 grid** (PC 2x2 / 모바일 세로): 현재월 ~ +3개월

### 날짜 셀 시각 표시
| 표시 | 의미 |
|------|------|
| 빨간 슬래시 + "휴무" | 임시 휴무 (특정 날짜만, closed_dates) |
| 회색 슬래시 + "정기휴무" | 정기 휴무 요일 (매주 반복, disabled_weekdays) |
| 오렌지 + "시간차단" | 그 날 시간대 차단 있음 (096, blocked_time_slots) |
| 초록 점 | 그 날 매장방문 예약 있음 |
| 보라 점 | 그 날 출장요청 예약 있음 |
| 오렌지 점 | 그 날 시간대 차단 건수 |
| 회색 비활성 | 과거 날짜 (변경 불가) |
| 우선순위 (라벨) | 임시휴무 > 정기휴무 > 시간차단 |

### 날짜 클릭 → 모달
1. **그날 예약 list** (있으면): 매장/출장 아이콘 + 고객명 + 전화번호 + 시간
2. **정기 휴무 요일 안내** (해당하면): "이 날짜는 정기 휴무 요일입니다 (매주 반복)"
3. **임시 휴무 사유 입력** (선택): 자유 텍스트 (예: "결혼식", "여름휴가")
   - **고객에게 노출 안 됨** — 사장님 내부 관리용
4. **시간대 차단 (096)**: 30분 단위 시작/종료 드롭다운 + 사유 → "추가". 한 날짜 여러 구간 등록 가능. 개별 삭제(휴지통).
   - 예: "14:00~16:00 병원" + "10:00~11:00 외부 일정" 따로 등록
   - 전일 휴무가 아닐 때만 표시 (전일 휴무면 어차피 종일 막힘)
5. **액션 버튼**:
   - "이 날짜 막기" / "휴무 해제" 토글
   - 예약 있는 날에도 막기 가능 (기존 예약은 그대로 유지)

### 휴무·차단의 영향
| 동작 | 결과 |
|------|------|
| 임시 휴무 등록 | 그 날짜 신규 고객 예약만 차단 (전일). 기존 예약 유지. 사장님 등록은 자유 |
| 정기 휴무 요일 추가 | 그 요일 신규 고객 예약 차단 (매주 반복). 기존 예약 유지. 사장님 등록은 자유 |
| **시간대 차단 (096)** | 그 시간 구간만 신규 고객 예약 차단 (모든 셀프예약). 기존 예약 유지. 사장님 등록은 자유 |
| 영업시간 변경 | 모든 셀프예약 폼 가용 슬롯 범위 즉시 변경 |
| 알림톡/리마인더/Google Calendar 동기화 | 모두 정상 유지 (블랙아웃 검증 0) |

### 자동 반영
- 상담 폼: `/api/consultation/public/slots`이 `closed_dates` + `disabled_weekdays` + **`blocked_time_slots`(096)** 반영
- 복원수리 직접방문 폼: `/api/repair/public/slots`이 동일하게 모두 반영 (양방향 충돌검사 자동)
- 사장님이 막은 직후 캐시 만료 후 고객 폼에 반영

### 휴무 사유 노출 여부
- 고객 폼: ❌ 노출 안 됨 (API 응답에 reason 자동 제외)
- 사장님 달력 관리: ✅ 모달에서 확인 가능
- 사용 예: "결혼식", "여름휴가", "외부 일정", "병원" 자유롭게 기록

### 블랙아웃 룰 (096 시간대 차단도 동일 — feedback_consultation_blackout_rule)
- 휴무·시간대 차단은 **고객 셀프예약 흐름에만** 적용
- 사장님 측 흐름(admin-create / suggest / 일정수동등록 모달)은 검증 0 — 막힌 시간에도 직접 등록 가능

## 1. 개요

상담관리는 **매장방문**, **출장요청**, **톡상담** 3가지 유형의 상담을 통합 관리합니다.

| 유형 | 설명 | 접수 경로 |
|------|------|-----------|
| 매장방문 | 고객이 매장에 직접 방문하여 상담 | GitHub Pages 폼 → Vercel API → Supabase |
| 출장요청 | 고객 위치로 출장 방문 상담 | GitHub Pages 폼 → Vercel API → Supabase |
| 톡상담 | 카카오톡을 통한 비대면 상담 | GitHub Pages 폼 → Vercel API → Supabase |

---

## 2. 화면 구성

### 상단 요약 카드
- **신규**: 미처리 접수 건수 (클릭 → 출장요청 탭 이동)
- **진행**: 현재 진행 중인 상담 건수
- **완료**: 이번 달 완료 건수
- **새로고침**: 외부 데이터 동기화

### 3개 탭
| 탭 | 내용 |
|-----|------|
| 매장방문 | 확정 일정 목록 + 달력 (PC: 3열 — 목록/달력/상세) |
| 출장요청 | 6개 서브탭 + 카카오맵 (PC: 3열 — 목록/지도/상세) |
| 톡상담 | 3개 서브탭 (신규/진행/완료) |

## 3. 매장방문

### 서브탭
- **확정**: 확정된 예약 일정
- **지난내역**: 완료/취소된 과거 내역

### 달력 (PC 우측)
- 월별 달력에 확정 일정 표시
- 초록 점: 매장방문 / 보라 점: 출장요청
- 날짜 클릭 → 해당 일 일정 목록 표시

### 가능한 액션
| 현재 상태 | 액션 | 결과 |
|-----------|------|------|
| 확정 (confirmed) | 상담 완료 | → completed |
| 모든 상태 | 취소 | → cancelled (확인 모달) |
| 완료 | 계약서 작성 | → /contracts/new로 이동 (고객 정보 자동 연결) |

## 4. 출장요청

### 서브탭 (6개)
| 탭 | 상태 | 설명 |
|----|------|------|
| 오늘출장 | confirmed (오늘) | 오늘 예정된 출장 |
| 신규접수 | pending_admin | 새로 들어온 요청 |
| 제안중 | suggested | 시간 제안 완료, 고객 응답 대기 |
| 일정재요청 | reschedule/change | 고객이 변경/재요청 |
| 확정 | confirmed | 일정 확정 완료 |
| 지난내역 | completed/cancelled | 완료 또는 취소 |

### 시간 제안 기능
- **대상**: 신규접수, 일정재요청 상태
- 최대 **3개 시간대** 제안 가능
- 고객의 가능요일/시간대 참고 표시
- 제안 후 → "제안중" 상태로 전환

### 카카오맵 (PC 중앙)
- 출장 요청 위치를 지도에 마커로 표시
- 서브탭 전환 시 해당 상태의 마커만 표시
- 마커 클릭 → 상세 패널에 해당 건 표시

### 가능한 액션
| 현재 상태 | 액션 | 결과 |
|-----------|------|------|
| 신규접수 | 시간 제안 | → suggested |
| 재요청 | 시간 제안 | → suggested |
| 확정 | 상담 완료 | → completed |
| 모든 상태 | 취소 | → cancelled |

## 5. 톡상담

### 서브탭 (3개)
| 탭 | 상태 | 설명 |
|----|------|------|
| 신규접수 | pending_admin | 카카오톡 접수 |
| 진행중 | in_progress | 상담 진행 중 |
| 완료 | completed/cancelled | 종료 |

### 가능한 액션
| 현재 상태 | 액션 | 결과 |
|-----------|------|------|
| 신규접수 | 상담 시작 | → in_progress |
| 진행중 | 상담 완료 | → completed |
| 모든 상태 | 취소 | → cancelled |

---

## 6. 상세 패널 (공통)

### 표시 정보
- 고객명, 전화번호 (탭하여 전화 가능)
- 방문 예정일/시간
- 주소 (출장의 경우)
- 접수 메모 / 재요청 메모 (분리 표시)
- 가능요일, 시간대 (출장의 경우)
- 상태 이력 (최근 5건)

### 완료 후 CTA
- 상담 완료 시 **"계약서 작성하기"** 링크 표시
- 클릭 → 계약서 작성 페이지로 고객 정보 자동 전달

---

## 7. 상태 흐름도

```
[접수] pending_admin
  ├─ 매장방문 → 자동 확정 (confirmed)
  ├─ 출장요청 → 시간 제안 (suggested) → 고객 선택 → 확정 (confirmed)
  └─ 톡상담 → 상담 시작 (in_progress)
       │
       ▼
[확정/진행] → 상담 완료 (completed)
       │
       ▼
[완료] → 계약서 작성 CTA
```

---

## 8. 대응필요 뱃지

각 탭에 빨간색 뱃지로 대응 필요 건수를 표시합니다:
- **출장요청**: 신규접수 + 재요청 건수
- **톡상담**: 신규접수 건수
- **매장방문**: 없음 (자동 확정)
