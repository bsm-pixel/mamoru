# 🔖 시리얼 관리 사용 매뉴얼

> 최종 업데이트: 2026-06-13 · 대상: 처음 쓰는 분도 따라할 수 있게

시리얼은 가위 한 자루마다 붙는 **고유 번호**예요. **정품 확인 + 평생 복원수리 보증 + 누가 어느 가위를 샀는지** 추적의 핵심이라, 절대 깨지면 안 되는 데이터입니다.

## 시리얼 번호 형식 (2026-06-11 확정)

**`MR{연도2자리}{5자리 번호}`** → 예: **`MR2610816`**
- MR = 마모루, 26 = 2026년, 10816 = 누적 번호
- **연도가 바뀌어도 번호는 0으로 리셋 안 됨** (계속 누적 → "갓 시작" 느낌·판매량 노출 방지)
- 기존 `13790001`대 옛 시리얼은 그대로 보존(신규부터 MR형식)
- 조회 시 하이픈·대소문자 무시 (`mr2610816`, `MR26-10816` 다 찾아짐)

## 1. 시리얼 관리 & 조회 화면

**메뉴**: 사이드바 → **CS → 시리얼 관리 & 조회**

한 화면에 탭 2개:
- **[시리얼 조회]**: 시리얼 하나 검색 → 제품·판매·고객·이력 전부 확인 + 교환
- **[제품별 관리]**: 제품 선택 → 시리얼 일괄/단건 생성·상태·위치 변경 + **라벨 출력**(🖨)

### 조회 검색
- 시리얼 번호 (예: `MR2610816`) 또는 바코드 입력 · 부분 일치도 가능

### 표시 정보 (위에서 아래로)
1. **시리얼 + 상태**: 시리얼 번호 + 상태 배지(재고/예약/판매완료/반품/불량) + 위치 배지(보관/준비/디스플레이)
2. **제품 정보**: 제품명, SKU, 카테고리, 가격
3. **판매 정보**: 판매번호, 판매일, 판매경로, 결제금액 — 우측에 **[⟷ 교환]** 버튼 (판매완료 상태에서만)
4. **고객 정보**: 성함, 연락처
5. **복원수리 이력**: 고객 전화번호로 매칭된 복원수리 건 (최근 5건)
6. **이동 이력**: 시리얼의 모든 변경 자동 기록 (생성·상태변경·창고이동·판매연결·해제·삭제 등)

## 2. 시리얼 교환 (⟷ 다른 판매와 양방향 교환)

### 언제 쓰나
판매 A에 시리얼 X 등록 + 판매 B에 시리얼 Y 등록 → **사장님이 둘이 바뀌어야 함을 발견**한 경우.

예) 사장님이 매장에서 A고객과 B고객에게 가위 1개씩 판매하면서 시리얼을 헷갈려 X와 Y를 서로 바꿔 등록한 경우.

### 흐름 (단순 4단계)
```
1. 시리얼 조회에서 시리얼 X 검색
2. 판매 정보 카드 우측 [⟷ 교환] 버튼 클릭
3. 모달에서 상대 시리얼 Y 번호 입력 + 엔터
4. 좌(X) / 우(Y) 정보 확인 → [교환합니다] 클릭
```

→ 토스트 "시리얼 교환 완료" + 화면 자동 갱신 + 두 판매의 고객 정보·시리얼 연결이 **동시에 교환**.

### 자동 가드 5겹 (잘못된 교환 차단)
| 상황 | 차단 메시지 |
|---|---|
| 같은 시리얼끼리 | "같은 시리얼끼리는 교환할 수 없습니다" |
| 한쪽이 판매 안 됨 | "두 시리얼 모두 판매완료 상태여야 교환할 수 있습니다" |
| 한쪽이 판매 미연결 | "판매에 연결된 시리얼만 교환할 수 있습니다" |
| 같은 판매 내 시리얼 | "같은 판매 안의 시리얼끼리는 교환이 무의미합니다" |
| **다른 제품의 시리얼** | "같은 제품의 시리얼끼리만 교환할 수 있습니다" |

→ 위 중 하나라도 걸리면 **[교환합니다] 버튼 회색**으로 비활성화.

### 주의
- 교환은 **시리얼 5개 필드만** 바꿈: 판매 연결 / 판매 항목 / 고객명 / 연락처 / 판매경로
- 시리얼 자체의 **물리적 위치, 판매 시각, 제품 정보**는 그대로 (실제로 가위가 안 움직였으니까)
- 한 번 교환하면 자동으로 **이동 이력**에 기록됨 → 나중에 추적 가능

### 다른 경우는?
- **새 판매에 들어갈 시리얼이 이미 다른 판매에 잘못 등록되어 있는 경우** → 판매 입력 화면에서 그 시리얼 번호 입력하면 "이전 판매에서 가져오기" 모달 자동 노출 (Phase A 단방향 이전)
- **시리얼 자체를 잘못 등록** (제품/번호가 틀림) → 별도 수정 흐름 필요 (현재 미구현, 향후 사이클)

## 3. 이동 이력 (자동 ledger)

### 자동 기록 대상
시리얼이 다음 중 하나라도 변경되면 **자동으로 이력 1건 추가**:
- 상태 (재고 ↔ 판매완료 ↔ 반품 ↔ 불량)
- 위치 (보관 ↔ 준비 ↔ 디스플레이)
- 판매 연결 (sale_item / offline_sale)
- 계약서 연결
- 제품 연결

### 표시 정보 (시리얼 조회 페이지 하단 카드)
- **액션 배지**: 생성 / 변경 / 삭제
- **변경 요약**:
  - 생성: "재고 / 준비" (초기 상태)
  - 변경: "상태: 재고 → 판매완료" / "위치: 준비 → 디스플레이" / "판매 연결됨" 등
  - 삭제: "마지막 상태: 판매완료"
- **시각**: 2026-05-18 22:30
- **변경자**: 사장님 이름 (또는 "시스템")

### 누가 만들었나 자동 추적
사장님 (또는 향후 직원)이 시리얼 관련 액션을 하면 자동으로 본인 ID 기록 → 추적 가능.

### 이력 삭제 불가 (위변조 방지)
- DB 레벨에서 **읽기 전용** (사장님조차 직접 수정·삭제 불가)
- 트리거가 자동 INSERT만 수행
- 만약 향후 운영 사고 발생 시 → 이력 보고 누가 언제 무엇을 변경했는지 100% 추적

## 4. 일상 운영 시나리오

### A. 가위 신규 등록
1. **시리얼 관리 & 조회 → [제품별 관리]** 에서 제품 선택 (또는 제품 상세 → 시리얼 관리)
2. **일괄 생성**: 수량만 입력 → `MR2610816`부터 자동 연속 채번 (시작번호 직접입력 불필요)
3. 상태: `재고`, 위치: `준비` 또는 `디스플레이`
4. → 이력에 "생성" 1건 자동
5. (선택) 시리얼 행 🖨 → 시리얼 라벨 출력 — [라벨 매뉴얼](MANUAL_LABEL.md)

### B. 판매 등록 (시리얼 매칭)
1. `+ 판매 입력` (판매 관리 페이지 상단 버튼)
2. 고객 + 제품 + 시리얼 선택 (재고 목록에서) — 또는 **시리얼 라벨 바코드를 스캔**하면 그 가위가 시리얼까지 자동 배정돼 담김 (출고 시 오배정 0)
3. 저장 → 시리얼 상태 자동으로 `판매완료(sold)`로 변경 + 고객 정보 매칭
4. → 이력에 "변경: 상태: 재고 → 판매완료, 판매 연결됨" 1건 자동

### C. 판매 취소·반품
1. 판매 상세 → 취소/반품 액션
2. 시리얼 자동으로 `재고(in_stock)` 복원 + 원래 위치(`previous_zone`)로 복귀
3. → 이력에 "변경: 상태: 판매완료 → 재고, 판매 해제됨" 1건 자동

### D. 시리얼 교환 (위 2번 흐름)
1. 시리얼 조회 → [⟷ 교환]
2. → 이력에 두 시리얼 모두 "변경: 판매 연결됨" 각 1건 자동

### E. 창고 이동 (준비 ↔ 디스플레이)
1. 제품 상세 → 시리얼 목록 → 이동
2. → 이력에 "변경: 위치: 준비 → 디스플레이" 1건 자동
