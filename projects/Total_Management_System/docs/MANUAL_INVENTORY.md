# 재고·창고 매뉴얼

> 최종 업데이트: 2026-05-13 — **매입(발주) 흐름 보강: 입고 전 잔금 지불 기록 + 입고검수(실수령 수량) + 입고 전 발주 수정**

## 2026-05-13 정리 — 매입(발주) 운영 (사장님 영향 큼)

매입관리 → 발주 클릭 → 우측 상세 패널에서:

| 상황 | 어떻게 |
|------|--------|
| **업체가 발송 시작했고 잔금만 먼저 보냈음 (물건 아직 안 옴)** | 액션 카드 → **"잔금 지불 처리 (입고 전)"** 클릭 → 잔금이 "지불완료 ✓"로 기록됨(미지급금 알림에서도 빠짐), 리스트·상세 뱃지가 **'결제완료'**로 바뀜. 물건 도착하면 그때 "입고 확인" → 재고 늘고 자동으로 "잔금완료" |
| **공장 제작 수량이 발주서와 다름 (입고 전 — 아직 배송중)** | 상세 상단 **"편집"** 버튼 → 품목 표에서 수량을 실제 제작 수량으로 수정 → 저장 → **총액·잔금 자동 재계산**. 그 다음 잔금 정산("잔금 지불 처리"). ※ 입고했거나 잔금 지불 기록한 뒤엔 편집 잠김 |
| **물건이 도착했는데 받은 수량이 주문과 다름** | "입고 확인 (재고 증가)" 클릭 → **입고검수 표**가 뜸 → 품목별 `주문 N / 실수령 [입력]` (기본=주문, 다른 것만 고침) → 아래 미리보기에 재계산된 총액·잔금·과지급 안내 확인 → "입고 확인". 재고는 **실수령 수량**만큼 늘어남(아임웹도). 발주서/주문 수량 기록은 그대로 보존, 화면엔 "입고 85 / 주문 90"으로 표시 |
| **나중에 5개 더 만들어져 옴** | 이미 입고 처리한 발주는 못 고침 → **새 발주 작성**해서 5개치 처리 |
| **덜 만들어져서 선납이 새 총액보다 많아짐 (과지급)** | 입고검수 또는 발주 편집 시 "⚠ 과지급 ₩X" 안내가 뜸 → 차액은 업체에서 환불받거나 다음 발주에서 차감(수동 정산) |

> 결제(돈)와 입고(물건)는 따로 처리해도 됩니다. 어느 쪽을 먼저 하든 둘 다 끝나면 발주 상태가 "잔금완료"가 됩니다.

## 📌 재고조사 인쇄 — 사용 가이드 (직원/사장님)

**언제 사용?** 매월/매주 또는 정기 재고조사 시 종이 들고 다니며 실재고 카운트할 때

### 단계별 사용법

#### 1️⃣ 화면 준비
1. 사이드바 → **창고·재고** 클릭
2. 어떤 제품을 조사할지 화면에서 미리 필터:
   - **카테고리 칩**: 전체 / 가위 / 빗 / 가위집 / 악세서리 / 기타
   - **저재고 토글**: 재고 적은 것만 (선택)
   - **미사용 토글**: 사용 안 하는 제품 숨김 (기본 ON)
   - **정렬 클릭**: 제품명 / 현재고 / 미입고 / 원가 (헤더 클릭으로 변경)

#### 2️⃣ 인쇄 시작
1. 우측 상단 **"재고조사 인쇄"** 버튼 클릭 (프린터 아이콘)
2. **미리보기 모달**이 열림 → 화면에 적용한 필터/정렬 그대로 반영됨
3. 카테고리별 자동 그룹화:
   - ▼ 블런트 (5종 · 소계 23개)
   - ▼ 틴닝 (...)
   - ...

#### 3️⃣ 출력 형태
| 컬럼 | 의미 |
|------|------|
| # | 순번 |
| 제품명 | 제품 이름 |
| SKU | 제품 코드 |
| 현재고 | 시스템상 총 재고 |
| 보관 / 준비 / 디스 | 창고별 수량 |
| **실측** (노란색) | **종이에 펜으로 직접 카운트한 수량 적기** |
| 비고 | 메모용 빈 칸 |

#### 4️⃣ 인쇄 → 종이 들고 카운트
1. 모달 우상단 **"인쇄"** 버튼 → 새 탭 열림 + 인쇄 다이얼로그
2. A4 종이로 출력 → 창고에서 실재고 카운트 → 노란 "실측" 칸에 펜으로 수량 적기
3. 차이 발견 시 비고란에 메모 (예: "파손 1", "반품 2")

#### 5️⃣ 차이 발견 시 시스템 반영
1. TMS → 창고·재고 → **"재고 조정"** 버튼 (재고조사 인쇄 옆)
2. 조정 모달에서 실측 수량으로 보정 + 사유 입력

## 1. 개요

재고 시스템은 **3단계 창고** + **시리얼 추적**으로 제품의 물리적 위치와 수량을 관리합니다.

---

## 2. 창고 구조 (3단계)

| 창고 | 코드 | 설명 | 시리얼 |
|------|------|------|--------|
| 보관 | raw | 미각인 원재고 (입고 시 여기로) | 없음 (raw_stock 수량만) |
| 준비 | ready | 각인 완료, 포장 완료, 판매 대기 | 시리얼 부여됨 |
| 디스플레이 | display | 전시용 샘플 (판매 불가) | 시리얼 부여됨 |

### 핵심 공식
```
아임웹 재고 = 보관(raw_stock) + 준비(ready 시리얼 수)
※ 디스플레이는 전시용이므로 판매 가능 재고에서 제외
```

---

## 3. 재고 현황 페이지

### 표시 정보
- 제품명 + SKU + 카테고리
- **현재고** (stock_quantity): 전체 재고 수량
- **창고별**: 보관/준비/디스플레이 각각 수량
- **입고대기**: 미입고 발주 수량
- **저재고 알림**: stock_quantity ≤ 3일 때 경고

### 카테고리 필터
전체 / 가위 / 빗 / 가위집 / 악세서리 / 기타

### 숨김 토글
재고 미사용(stock_quantity = -1) 제품 숨김/표시

---

## 4. 시리얼 관리

### 시리얼 등록
1. 제품 상세 → **시리얼 등록** 버튼
2. 시작번호 자동 입력 (이전 번호 이어서)
3. 수량 입력 (1~100개)
4. 등록할 창고 선택 (보관/준비/디스플레이)
5. **등록** → 보관창고(raw_stock)에서 차감, 시리얼 생성

### 시리얼 번호 형식
```
MM-{SKU}-{YYYYMMDD}-{SEQ}
예: MM-BL001-20260330-001
```

### 시리얼 상태
| 상태 | 설명 |
|------|------|
| in_stock | 재고 (판매 가능) |
| reserved | 예약됨 |
| sold | 판매 완료 |
| returned | 반품 |
| defective | 불량 |

### 창고 이동
- 시리얼 관리 페이지에서 개별 또는 일괄 이동 가능
- in_stock 상태 시리얼만 이동 가능
- 이동 시 stock_quantity는 변하지 않음 (물리적 위치만 변경)

---

## 5. 재고 변동 경로

| 이벤트 | stock_quantity | raw_stock | 비고 |
|--------|---------------|-----------|------|
| 매입 입고 | +N | +N | 보관창고에 입고 |
| 시리얼 등록 | 변화 없음 | -N | raw→ready 전환 |
| 온라인 주문 결제 | -N | -N | 보관에서 차감 |
| 온라인 주문 취소 | +N | +N | 보관으로 복원 |
| 오프라인 판매 B2C | -N | 변화 없음 | 시리얼(준비)에서 sold |
| 오프라인 판매 B2B | -N | -N | 보관에서 직접 출고 |
| 판매 취소 | +N | (B2B만 +N) | 시리얼은 원래 zone 복원 |
| 수동 조정 | ±N | ±N | 실사 보정/파손/반품 등 |

---

## 6. 아임웹 재고 동기화

### 동기화 방향
- **TMS → 아임웹**: 재고 변동 시 자동 push (실시간)
- **아임웹 → TMS**: 신규 상품만 (기존 상품은 TMS가 마스터)

### TMS = 운영 마스터 원칙 (2026-05-07 확정)
아임웹 상품 동기화 시 **다음 필드는 아임웹 값으로 덮어쓰지 않습니다**:
| 필드 | 이유 |
|------|------|
| `stock_quantity` (재고) | 재고 양방향 실시간 sync는 별도 경로로 처리. 동기화가 덮어쓰면 카운트 충돌 |
| `is_active` (활성) | 아임웹에서 "품절" 표시해도 TMS 창고재고/판매 흐름에선 계속 노출되어야 함 |

→ 아임웹 "품절" ≠ TMS 비활성. 아임웹은 단지 온라인 판매 채널 표시일 뿐, 운영(오프라인 판매·재고 추적)은 TMS에서 계속.
→ 비활성 처리는 **TMS 제품 페이지 → "비활성" 토글**로만 결정.

### 디스플레이 제외
아임웹에 push하는 재고에서 디스플레이 시리얼 수는 **자동 차감**됩니다.
```
아임웹 재고 = stock_quantity - 디스플레이 시리얼 수
```

### 동기화 시점
- 매입 입고 확인 시
- 판매 등록/취소 시
- 온라인 주문 동기화 시
- 재고 수동 조정 시

---

## 7. 재고 수동 조정

1. 재고 페이지 → **재고 조정** 버튼
2. 제품 선택
3. 조정 유형: 실사 보정 / 파손·불량 / 반품 입고 / 기타
4. 수량: +N (증가) 또는 -N (감소)
5. 사유 입력
6. → stock_quantity + raw_stock 동시 반영
7. → 아임웹 자동 동기화
8. → stock_adjustments 이력 기록

## 8. QR 인증 (시리얼 검증)

각 시리얼에 고유 `verify_token`이 생성됩니다.
- QR 코드로 제품 인증 가능 (/api/verify/[token])
- 로그인 불필요 (공개 API)
- 표시: 제품명, 판매 상태, 판매일
- 시리얼 번호는 보안상 비표시
