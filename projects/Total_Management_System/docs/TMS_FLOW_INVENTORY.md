## 2026-11-09 — 상품명·판매가 = TMS에서만 고친다 (아임웹 자동 반영, 사장님 확정)
- 제품 상세·일괄 수정에서 이름 저장 → `PATCH /api/products/[id]` → `renameImwebProduct()` → 아임웹 새 OpenAPI `PATCH /products/{prodNo}` (multipart `unitCode`+`productName`)
  - 실측: 이름만 보내면 이름·수정시각 외 전 칸(상세설명·가격·재고·상태·이미지) 그대로. 결제명·SEO 제목은 전 상품 비어 있어 상품명을 따라감
  - 판매가: `updateImwebPrice()` → `PATCH /products/{prodNo}/price` (JSON `unitCode`+`price`). 실측: 판매가 외 그대로. 정가<새 판매가면 아임웹 거절(30036) → 실패 알림
  - 바뀐 때만 보냄(다른 칸 저장엔 안 보냄). `sync_imweb:true` = 같아도 다시 보냄(「아임웹을 TMS 값으로 다시 맞추기」·일괄 재시도). 응답 `imweb:{synced[],errors[]}`
  - 실패해도 TMS 저장은 유지 + 화면에 분명히 알림(토스트). 아임웹에서 삭제된 상품 = 「아임웹에 이 상품이 없습니다」
- 상품 동기화(설정 버튼)는 **이미 있는 제품의 이름·판매가를 덮어쓰지 않음** — 다르면 「아임웹과 이름/판매가가 다른 상품」으로 알림만. 신규 생성 때만 아임웹 값
- 주문·시리얼·재고 연결은 상품번호(`imweb_product_no`) 기준이라 이름 변경 영향 없음. 과거 판매·주문은 당시 이름 그대로(`product_name` 스냅샷)
- ⚠️ 이름 기준 조회 1곳: 네이버 리뷰 일괄등록이 `products.name`으로 제품군을 찾음 → 옛 이름 리뷰는 제품군 비어 들어감
- 🐞 고침: 상품 동기화가 v2 `page` 파라미터를 써서 **최신 50개만 3번 처리**하던 것 → `offset`=페이지 번호(실측). 이제 101개 전수
- 정리(11-09): 가격 다르던 6개(A3 4종·A1-2523-PT·R4-58DRY)와 IW-81 이름(A2-2523-PT)을 TMS 값으로 아임웹에 맞춤 → 차이 0

## 2026-10-14 — 반품창고 → 재판매 / 불량 (`/api/inventory/return-release`)
```
반품·교환 회수품 → 반품창고 (시리얼: status=returned·zone=return / 비시리얼: products.return_stock)
  · 현재고(stock_quantity)·아임웹 미포함, 판매 입력 시리얼 목록(ready·display in_stock만)에 안 뜸
제품 상세 「반품창고 · 검수 대기」 카드 (components/inventory/return-stock-card.tsx)
  [재판매] 시리얼 → in_stock + 판매대기/진열, stock_quantity +1 (raw 불변)
           비시리얼 → return_stock −1, raw_stock +1, stock_quantity +1
           공통 → 아임웹 +1 (updateImwebStock), stock_adjustments(type=return, +1)
  [불량]   시리얼 → status=defective / 비시리얼 → return_stock −1. 재고·아임웹 변화 0, stock_adjustments(type=damage, 0)
```

- 시리얼 갱신은 `status='returned'` 조건부(중복 클릭 409). 이력은 DB 트리거 audit log 자동.
- 🚨 판매 입력에서 반품 시리얼을 직접입력하면 raw_stock 이 −1 돼 드리프트 → 반드시 [재판매] 먼저.

## 2026-05-13 — 매입(발주 → 입고) 흐름 (현행)

상태: `작성중(draft) → 발주완료(ordered) → 선납완료(deposit_paid) → 입고완료(received) → 잔금완료(balance_paid)` / `취소(cancelled)`

**결제(돈)와 입고(물건)는 독립** — 어느 순서로 하든 둘 다 끝나면 자동 `잔금완료`:
- **선납 처리**: `발주완료`/`작성중`에서 선납금 입력 → `선납완료`. `balance_amount = 총액 − 선납`.
- **잔금 지불 처리(입고 전)**: `발주완료`/`선납완료` + 잔금>0 + 미기록 → 잔금을 `지불완료`로 기록(`balance_paid_at`, `balance_amount=0`), 상태는 유지(입고 흐름 위해). (업체가 발송 시작했고 잔금만 먼저 보낸 경우). 이 상태(`ordered`/`deposit_paid` + `balance_paid_at`)는 리스트·상세 뱃지가 **'결제완료'**(emerald)로 표시 — '선납완료'로 보여 잔금 남은 것처럼 오해하는 것 방지.
- **잔금 완료**: `입고완료`에서 → `잔금완료`(terminal) + `balance_paid_at` + `balance_amount=0`.
- **입고 확인 → 입고검수 모달**: `발주완료`/`선납완료`에서. 품목별 `주문 수량 / 실수령 수량` 입력(기본=주문). 확인 시 ① 재고 += 실수령(아임웹 동기화 포함) ② 품목별 `received_quantity` 확정 기록(`quantity`(주문)는 보존) ③ 실수령 ≠ 주문이면 `total_amount`·`supply/vat`·`balance_amount` 재계산(환율·부가세 유형 반영, 선납 > 새 총액이면 잔금 0·과지급 화면 안내) ④ 상태 → `입고완료`(잔금 이미 냈으면 `잔금완료`). **멱등성 가드**: 이미 입고됐으면 거부(재고 중복 증가 방지).
- **발주 품목 수정**: `작성중`/`발주완료`/`선납완료` + 잔금 미지불 + 미입고 일 때 "편집" 가능 → 품목 변경 시 `total_amount`·`balance_amount` 자동 재계산. 입고·잔금지불·취소 이후엔 잠김. (공장 제작 수량이 발주와 다를 때 발주서를 현실에 맞게 갱신)
- **취소**: `입고완료`/`잔금완료` 이후엔 불가. 취소 건은 영구 삭제 가능.

DB: `purchase_orders.deposit_paid_at`, `balance_paid_at` (결제 시점 플래그) / `purchase_order_items.received_quantity`(입고검수 실수령, NULL=입고 전). 마이그레이션 081.

## 1. 전체 흐름

```
[아임웹 상품 등록]
       │
       ▼
[TMS 설정 > 상품 동기화] ──→ TMS 제품 자동 생성
       │                      (매입가/매입처는 TMS에서 수동 편집)
       ▼
[제품 목록] ← 아임웹 판매 상품 (BL/TH/LO/SL)
[부자재]   ← TMS 직접 등록 (박스, 포장재 등 — 아임웹 무관)
```

**상품 동기화 연결 규칙 (product-sync.ts, 2026-10-29 화면 안내 추가)**
1. 아임웹 상품번호가 같은 TMS 제품 → 갱신 (SKU는 아임웹 「자체 상품코드」 또는 `IW-번호`로 덮어씀)
2. 없으면 TMS SKU = 아임웹 「자체 상품코드」인 제품 → 연결
3. 그래도 없으면 `IW-번호`·카테고리 BL로 새로 생성 (= TMS에 먼저 만든 제품과 **중복**)
- TMS에서 먼저 등록할 때: 제품 상세의 **「아임웹 연동 매칭 코드」(=SKU)** 를 아임웹 「자체 상품코드」에 똑같이 입력 → 설정 › 시스템 › [상품 동기화]
- `IW-` 제품의 「접두어 불일치」 경고는 숨김 — 재채번해도 1번 규칙으로 되돌아감

```

[B2B 거래처] ← 딜러(납품처) + 아카데미(납품처) + 매입처(공장)
               └ 서브탭: 딜러 | 아카데미 | 매입처

       ┌──────────────────────────────────────┐
       │           재고 변동 경로              │
       ├──────────────────────────────────────┤
       │ 발주 입고     → TMS +N → 아임웹 +N   │
       │ 오프라인 판매 → TMS -N → 아임웹 -N   │
       │ 온라인 주문   → TMS stock -N + raw -N   │
       │               → 아임웹 -N (디스플레이제외)│
       │ 수동 조정     → TMS ±N → 아임웹 ±N   │
       │ 취소/환불     → TMS +N (자동 복구)    │
       └──────────────────────────────────────┘
       │
       ▼
[회계] ← 매출/매입/COGS/마진/미지급금/미수금
```

## 3. 매입 (발주) 프로세스

```
[매입처 등록] ← 상품·재고 > 매입처 > "매입처 추가"
       │        (업체명, 사업자번호, 대표자, 담당자, 연락경로)
       ▼
[발주 작성] ← 매입관리 > "발주 작성"
       │      매입처 드롭다운 선택 → 제품/수량 선택
       │      PO 번호 자동 채번: PO-YYYYMMDD-NNN
       ▼
[발주 확정] → status: ordered
       │
       ▼ (선택)
[선납 처리] → status: deposit_paid
       │      deposit_amount 기록, balance_amount 자동 계산
       ▼
[입고 확인] → status: received ★
       │      TMS 재고 +N (멱등성 가드: 1회만 실행)
       │      아임웹 재고 +N (재고 관리 상품만)
       ▼
[잔금 완료] → status: balance_paid
```

### 상태 전이 규칙
```
draft → ordered → deposit_paid → received → balance_paid
                       │              ↑
                       └──────────────┘ (deposit 없이 바로 입고 가능)

입고 이후 취소 불가
이미 received 상태에서 재클릭 → 409 에러 (재고 중복 방지)
```

## 4. 부자재 관리

```
[부자재 페이지] ← 상품·재고 > 부자재
       │
       ├── 부자재 추가 (이름, 주문 링크, 메모)
       │
       ├── 상태 토글 (뱃지 클릭)
       │   충분 → 주문필요 → 주문완료 → 충분 (순환)
       │
       └── "주문하기" 링크 → 외부 쇼핑몰 바로 이동

재고 숫자 관리 없음 — 상태 뱃지만으로 관리
발주 시스템 사용 안 함
```

## 5. 재고 수동 조정

```
TMS 재고 페이지 > "재고 조정" 버튼
       │
       ▼
[조정 모달]
  → 제품 선택
  → 조정 유형: 실사 보정 / 파손·불량 / 반품 입고 / 기타
  → 수량: +N 또는 -N
  → 사유 입력
       │
       ▼
  → TMS 재고 반영 (음수 방지)
  → 아임웹 재고 자동 반영 (재고 관리 상품만)
  → stock_adjustments 테이블에 이력 기록
```

## 6. 회계 연동

```
[회계 페이지]
  ├── 매출 요약: 오프라인 판매 집계
  ├── 매입 요약: 발주 집계
  ├── 매출이익: 매출 - COGS (제품별 price_purchase 기반)
  ├── 제품별 랭킹: 매출순/마진순
  ├── 매입처별 지출: 매입처별 총 지출액
  ├── 미지급금: 미완료 PO의 매입처별 잔금
  ├── 미수금: 고객별 outstanding_balance
  └── 엑셀 내보내기: 매출/매입/마진 분석
```
