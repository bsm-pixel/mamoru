## 0. 복원수리 한눈에 (먼저 읽기)

고객의 **무뎌지거나 상한 가위를 복원·수리**하는 흐름을 접수부터 출고까지 관리합니다.

**진행 방식 3가지** (고객이 접수 때 선택):
- **방문수거**: 택배로 받아 → 수리 → 다시 택배 발송
- **직접발송**: 고객이 직접 보냄 → 수리 → 발송
- **직접방문(당일수리)**: 매장 방문 예약 → 즉석 수리 → 그 자리 수령 (송장·수거 없음)

**기본 흐름**: `접수 → (수거/방문) → 입고·검수 → 비용안내 → 수리 → 출고 → 완료`. 각 단계에서 고객에게 알림톡 자동 발송.

**기본 동선**: 사이드바 → **복원수리** → 상단 카드(신규/진행/미입금)로 필터 → 건 클릭 → 우측에서 처리(검수→비용안내→입금확인→출고).

> 💡 매출은 3곳에서 발생(접수시스템 / 매장판매 / 거래처납품)해서 대시보드가 "복원수리 전체"로 합산합니다. (아래 2026-05-13 참조)

## 2026-05-13 정리 — 복원수리 매출/입력 경로 (사장님 영향 큼)

복원수리는 3개 채널에서 발생하고, 대시보드·회계가 셋을 합산해 "복원수리 전체"로 보여줍니다:
- **A채널 — 접수시스템 (`/repairs`)**: 고객이 접수페이지로 가위 보냄 → 수거·검수·수리·출고. (기존 흐름 그대로)
- **B채널 — 매장 판매 (`/sales/new` "복원수리" 모드)**: 매장에서 즉석으로 복원수리 판매. 마모루(기본 1만)/타사(기본 2만) 자루 수 + 단가 + 배송비 토글. 저장 시 `category='RS'`. 마모루/타사 구분됨.
- **C채널 — 납품 (`/deliveries` "+B2B수리")**: B2B 거래처(딜러/아카데미) 복원수리. 마모루/타사 구분 없이 자루당 거래처 단가. **거래처 마스터(고객 상세, 딜러·아카데미)에 "복원수리 기본 단가(자루당)"를 입력해두면** 거래처 선택 시 단가 자동 채움. 배송비 버튼도 있음.
- **자루(수량) 기준 카운트**: 메인 대시보드 복원수리 카드 "(N자루)" / 회계 모두 자루 수 기준. **배송비 항목은 복원수리 매출 금액엔 포함되지만 "자루 수"엔 안 들어감** (접수시스템 수거·배송비와 동일 정책).
- 회계 리포트(`/reports`) → "복원수리" 탭: `접수시스템 / 판매 RS / 납품 RS` 채널별 금액·건수.

## 1. 개요

복원수리는 고객 가위의 복원·수리를 접수부터 출고까지 관리합니다.

**접수 경로**: 고객 접수 페이지(GitHub Pages) → Vercel API → Supabase → TMS

→ 접수 시점에 phone 기반 customer 자동 매칭 (072): 같은 phone이면 기존 customer로 link, 없으면 신규 생성. 사장님이 직접 입력 안 해도 단골 자동 추적.

## 4. 상세 패널

### 비용 섹션
- 수리비 / 수거비 / 합계 표시
- 수동 편집 가능 (비용안내 전)
- 무상 처리 (합계 0원) 지원

### 입금 상태
- 입금완료: 녹색 체크 + 일시 표시
- 미입금: **입금확인** 버튼 표시
  - 알림톡 발송 여부 체크박스 (해제 시 내부 처리만)

### 검수 / 수리내역서 작성 (Inspection) — v2 핀 마킹 (2026-05-29)
- "내역작성하기" → 가위별 탭(+추가 로 여러 자루). 종류 선택 → 사진 촬영/업로드.
- **사진 위에 상처를 직접 표시**:
  - 위치형 핀(한 번 **탭 = ✓ 즉시**, 마크 탭 = 삭제): 무뎌짐(**드래그 = 범위 선**) · 찍힘 · 빗살 손상(틴닝만 노출) · 부품 문제 · 스토퍼 문제
  - 플래그(위치 없이 **카드 우측 상단** 표기): 장력조절 필요 · 밸런스 불균형 · 날각 문제
- **진단 및 내역(가위별)**: 핀/플래그를 표시하면 해당 진단 멘트가 **자동 삽입**됩니다 (예: 찍힘 → "찍힌 상처의 경계선까지 복원완료"). 가위 종류별 멘트 칩(블런트/틴닝/장가위/슬라이싱)도 추가 가능, 직접 수정도 됨.
- 사진 **다시 촬영** 시 그 가위의 마킹·진단 내역 초기화. 저장 시 검수 완료 + 비용 자동 반영.
- 고객은 알림톡 [수리내역 조회]에서 **가위 사진 위 마킹(점·선·플래그) + 가위별 진단 및 내역**을 그대로 봄.
- 모바일: 세로 화면 사용(가로 시 "세로로 돌려주세요" 안내). 카메라 촬영 후 화면 유지(목록 튕김 없음).
- 구조·파일 상세: [TMS_FLOW_REPAIR.md](TMS_FLOW_REPAIR.md) 2026-05-29 섹션.

## 5. 액션 버튼

### 비용안내 발송
- **대상 상태**: intake ~ cost_notified
- 클릭 → 확인 모달 → 고객에게 **비용안내 알림톡** 발송
- 자동으로 `cost_notified → repairing` 전환 (작업시작 별도 클릭 불필요)
- 0원(무상) → 자동 입금완료 처리

### 입금확인
- **대상 상태**: cost_notified ~ shipped (paid_at 없을 때)
- 확인 모달에서 알림톡 발송 여부 선택 가능
- 상태 변경 없이 `paid_at` 플래그만 설정

### 출고 섹션
- cost_notified 이상 상태에서 표시
- **송장 생성**: 롯데택배 ALPS API 연동
- **출고완료**: ready_to_ship + 송장 있을 때 → shipped
- **송장 취소**: 집하 전에만 가능

### 상태 전환 버튼
- 현재 상태에서 가능한 다음 상태만 표시
- 모든 전환에 확인 모달 적용

### 취소
- 모든 비터미널 상태에서 가능
- danger 모달로 확인

## 6. 상태 흐름도

```
intake (접수)
  → pickup_scheduled (수거예약)
    → picked_up (수거완료)
      → inspecting (입고·검수)
        → cost_notified (비용안내)
          → repairing (수리중) ← 비용안내 시 자동 전환
            → ready_to_ship (출고대기)
              → shipped (출고완료)
                → delivered (배송완료)
                  → completed (완료)

어디서든 → cancelled (취소) 가능
```
