## 왜 만들었나 — 무너져 있던 것

액션이 늘어날 때마다 버튼을 **아래로 하나씩 쌓아** 왔다. 그 결과:

| 화면 | 증상 |
|---|---|
| 납품 | 가장 큰 검은 버튼이 제일 안 쓰는 **[송장 재발급]**, 주 행동인 [출고 완료]는 흰 버튼으로 박스에 갇힘. 출고 끝난 뒤에도 [송장 취소]만 빨갛게 덩그러니 남음 |
| 복원수리 | 비용 카드 안에 입금확인·비용안내·상태전이·취소·삭제가 섞임. 출고 카드엔 6개 액션 평면 나열. 재수거(파랑)·재작업(주황) 채움 버튼 |
| 판매 | 보라 채움 [제품 교환]이 본문 한가운데. 반품·취소 묶음이 **택배 섹션보다 위** |
| 주문 | [주문 취소]·[송장 취소]가 빨간 full-width 버튼으로 주 액션과 같은 무게. 준비표보다 위 |
| 반품 | 안내문·주 액션·보조 전이·취소가 한 덩어리. **[취소]가 보조 버튼과 같은 줄** (오클릭 위험) |

공통 원인: **"무엇이 지금 할 일인가"를 시각적으로 정하는 규칙이 없었다.**

## 규칙 — 액션 영역은 항상 이 순서로만 쌓는다

```
① ActionNote    지금 상태 한 줄 (읽기 전용, 버튼 아님)
② 주 액션        검은 Button 1개 — "지금 눌러야 할 것" 하나만
③ 결제          남아있는 결제 처리 (흰 Button)
④ MoreActions   드문 것·되돌리기 → 접어둔다 (평소엔 글자 한 줄)
⑤ DangerZone    파괴적 액션. hairline 아래 회색, hover 에서만 빨강
```

⚠️ **슬롯 순서를 바꾸지 말 것.** 5개 화면이 같은 순서라서 사장님이 화면을 옮겨도 눈이 같은 자리를 본다.
특히 ④⑤는 **문서·정보 섹션(준비표·거래명세서·배송정보)보다 아래**에 와야 한다 — 이 순서가 뒤집혀 있던 게 판매·주문의 실제 버그였다.

### 구성요소

| 컴포넌트 | 쓰는 곳 | 비고 |
|---|---|---|
| `ActionNote` | ① 상태 한 줄 | `tone`: `wait`(노랑) · `done`(초록) · `muted`(회색) / `title` 굵게 + `meta` 옆에 보조정보 |
| `Button` | ② 주 액션 | 기본(검정) **1개만**. 같은 단계에 또 있으면 `variant="secondary"` |
| `MoreActions` | ④ 접힘 | `label`은 질문형 — "다르게 보냈어요", "잘못 처리했나요?", "다른 처리 방법", "반품 · 교환 · 취소" |
| `SubtleButton` | ④ 안쪽 보조 액션 | 파괴적이지 않은 것 (합포장·직접수령·재수거·교환) |
| `DangerZone` + `DangerLink` | ⑤ | 평소 회색, hover 에서만 빨강. 절대 채움 버튼 금지 |

### 화면별 주 액션(②)

| 화면 | 상태 → 주 액션 |
|---|---|
| 납품 | 작성중=납품확정 / 확정+송장없음=송장생성 / 확정+송장=출고완료 |
| 복원수리 | 신규접수=입고&비용안내(직접방문=방문확정·현장결제, 방문수거=수거접수) / 작업중=출고대기 / 출고대기=송장생성 or 출고완료 / 배송완료=완료 |
| 판매 · 주문 | 상단 `PrimaryActionBar`(「⚡ 다음 할 일」)가 ②③을 맡는다 |
| 반품 | `RETURN_PRIMARY_NEXT[status]` |

## 색 규칙 (브랜드 모노크롬)

- 채움 버튼은 **검정 하나**. 파랑·보라·주황·빨강 채움 버튼 **금지**
- 상태 표시에만 색을 쓴다: 대기=amber-50 / 완료=green-50 / 중립=stone-50
- 빨강은 **hover 에서만** 등장 (DangerLink)

## 확인 모달

파괴적이거나 되돌리기 어려운 액션은 `ConfirmModal` 경유. `window.confirm` 금지 (2026-09-15 복원수리 3곳 제거).
송장 취소 모달에는 **"먼저 롯데 ALPS 에서 집하취소를 완료해주세요"** 를 반드시 넣는다 — TMS 는 기록만 정리한다
([TMS_FLOW_AUTO_DELIVERY.md](TMS_FLOW_AUTO_DELIVERY.md) 참고).

## 새 화면에 적용할 때 (체크리스트)

1. 이 화면에서 **지금 눌러야 할 것 하나**가 상태별로 무엇인지 적어본다 → ②
2. 나머지는 전부 ④ 접힘. "가끔 쓴다 / 되돌리기다" 싶으면 접는다
3. 삭제·취소는 ⑤. hairline 으로 분리
4. 카드 역할을 섞지 않는다 — **정보 카드에 버튼을 넣지 않는다** (복원수리 비용 카드가 그랬다)
5. 1초 테스트: 화면을 1초 보고 눈 감았을 때 **검은 버튼 하나**가 잔상으로 남는가?

## 검증 방법 (로그인 없이 화면 보기)

로그인 게이트 때문에 실화면을 못 띄울 때, 아래를 **임시로** 만들어 헤드리스 캡처하고 **반드시 원복**한다.

1. `src/app/devpreview/page.tsx` — 패널을 상태별로 나열. 데이터는 `queryClient.setQueryData(['<key>', id], mock)` 로 주입(네트워크 0)
2. `src/middleware.ts` 인증 분기 앞에 `if (pathname.startsWith('/devpreview')) return supabaseResponse;` 한 줄
3. `npm run dev` → puppeteer-core 로 `fullPage` 캡처 (접힘 열기 전/후 2장)
4. **원복**: middleware 되돌리고 devpreview 삭제 → `git status` 로 확인 후 커밋
