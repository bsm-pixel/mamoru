## 시나리오 1: 온라인 주문 배송

> 아임웹 → TMS → 롯데택배 → 아임웹

### 흐름

```
고객이 아임웹에서 주문+결제
        │
        ▼
 ┌──────────────────────────────────┐
 │ 주문 동기화                       │
 │ Vercel Cron (자동, 주기적)        │
 │ 또는 TMS 주문관리 "동기화" 버튼    │
 │                                  │
 │ GET /api/cron/sync-orders        │
 │ POST /api/imweb/sync             │
 └──────────┬───────────────────────┘
            │ 아임웹 API v2 조회
            │ → Supabase orders upsert
            │   (imweb_order_no 기준)
            ▼
 ┌──────────────────────────────────┐
 │ TMS 주문관리 (/orders)            │
 │                                  │
 │ 주문 확인 → [송장생성] 클릭       │
 │ POST /api/lotte/book             │
 └──────────┬───────────────────────┘
            │ ALPS API 호출
            │ → 송장번호(invNo) 발급
            │ → orders.status = 'shipping'
            ▼
 ┌──────────────────────────────────┐
 │ 아임웹 송장 자동 반영              │
 │ PATCH /v2/prod-orders/*          │
 │                                  │
 │ ✅ 배송대기 상태 → 자동 성공       │
 │ ❌ 다른 상태 → needsManual=true   │
 │    (아임웹에서 수동 입력 필요)      │
 └──────────┬───────────────────────┘
            ▼
      롯데택배 배송 진행
      GET /api/lotte/track 로 추적 가능
```

### 실제 예시

1. 고객 "김민수"님이 아임웹에서 **마모루 블런트 7인치** 주문 (카드 결제)
2. TMS Cron이 자동 동기화 → 주문관리 목록에 신규 주문 표시
3. 관리자가 TMS에서 **[송장생성]** 클릭
4. 롯데택배 송장 자동 발급 → 아임웹에 송장번호 자동 반영
5. 고객에게 배송 시작 알림 → 배송 추적 가능

### 주의사항

- 아임웹 송장 반영은 **배송대기(STANDBY)** 상태에서만 자동 성공
- 입금 전(BEFORE_DEPOSIT) 등 다른 상태면 아임웹에서 수동 처리 필요
- TMS 관리 상태(`cancel_pending`, `shipping`)는 동기화 시 덮어쓰지 않음

### 흐름

```
        │
        ▼
 ┌──────────────────────────────────┐
 │ TMS 판매등록 (/sales/new)         │
 │                                  │
 │ - 고객 선택 (또는 신규등록)        │
 │ - 제품 선택 + 수량 + 결제방법      │
 │ POST /api/sales                  │
 └──────────┬───────────────────────┘
            │ Supabase 저장
            │ 판매번호: OS-YYYYMMDD-NNN
            ▼
 ┌──────────────────────────────────┐
 │ /sales/[id] 판매 상세 페이지       │
 │                                  │
 │ - 판매 정보 확인                   │
 │ - 결제 상태 관리                   │
 └──────────────────────────────────┘
```

### 실제 예시

1. 매장 방문 고객 "박미영"님에게 **마모루 세닝 6인치** 2개 현금 판매
2. TMS `/sales/new`에서 판매 등록 (고객 + 제품 + 수량 + 결제방법)
3. Supabase에 판매 기록 저장, 상세 페이지에서 확인

## 시나리오 3: 복원수리 전체 플로우

> 접수 → 수거 → 입고/검수 → 비용안내 → 입금 → 수리 → 출고 → 만족도

### 흐름

```
고객이 접수 페이지에서 수리 신청
        │
        ▼
 ┌──────────────────────────────────┐
 │ GAS 웹앱 → Google Sheets 저장    │
 │ POST /api/repair/sync            │
 └──────────┬───────────────────────┘
            │ Supabase repairs upsert
            │ status = 'intake' (신규접수)
            ▼
 ┌──────────────────────────────────┐
 │ TMS 복원수리 대시보드 (/repairs)   │
 │ [신규접수] 탭에 표시               │
 │                                  │
 │ ▸ 방문수거 → pickup_scheduled    │
 │   (롯데택배 수거 예약)             │
 │ ▸ 택배/직접방문 → cost_notified   │
 │   (수거 단계 스킵)                │
 └──────────┬───────────────────────┘
            ▼
 ┌──────────────────────────────────┐
 │ 입고 + 검수                       │
 │ /repairs/[id] 상세 페이지          │
 │                                  │
 │ 가위별 상태 입력:                  │
 │ - 날 상태 / 손잡이 상태 / 사진     │
 │ - 수리 항목 + 비용 산정            │
 │ POST /api/repair/[id]/inspect    │
 │                                  │
 │ → 비용안내 알림톡 발송              │
 │   "총 수리비 35,000원"            │
 └──────────┬───────────────────────┘
            │ 고객 입금 확인
            │ paid_at 설정 (독립 플래그)
            ▼
 ┌──────────────────────────────────┐
 │ status → repairing (수리중)       │
 │ ... 수리 작업 진행 ...             │
 │                                  │
 │ 수리 완료                         │
 │ status → ready_to_ship (출고대기) │
 └──────────┬───────────────────────┘
            ▼
 ┌──────────────────────────────────┐
 │ [출고] 클릭                       │
 │ POST /api/repair/[id]/ship       │
 │                                  │
 │ 롯데택배 ALPS → 송장 발급         │
 │ status = 'shipped'               │
 └──────────┬───────────────────────┘
            ▼
      롯데택배 배송
            │
            ▼
      delivered → completed
      (만족도 조사 알림톡 발송)
```

### 상태 전이 다이어그램

```
intake ─┬─→ pickup_scheduled ──→ cost_notified ──→ repairing ──→ ready_to_ship ──→ shipped ──→ delivered ──→ completed
        │                                │
        └────────────────────────────────┘   (택배/직접방문은 pickup 스킵)

        * 어느 단계에서든 → cancelled 가능 (shipped 이후 제외)
        * paid_at 는 상태와 독립적으로 관리
```

### 실제 예시

1. "이수진"님이 접수 페이지에서 **마모루 블런트 7인치** 복원수리 신청 (택배 발송)
2. GAS → TMS 자동 동기화 → [신규접수] 탭에 표시
3. 관리자가 접수 확인 → 상태: `cost_notified`
4. 가위 도착 → **검수 진행** (날 상태, 손잡이 상태, 사진 첨부, 비용 산정)
5. **비용안내 알림톡** 발송 → "총 수리비 35,000원"
6. 고객 입금 → `paid_at` 체크 → 상태: `repairing`
7. 수리 완료 → 상태: `ready_to_ship`
8. **[출고]** 클릭 → 롯데택배 송장 자동 발급 → 배송
9. 배송 완료 → **만족도 조사 알림톡** 발송

## 시나리오 4: 주문 취소 처리

> 고객 취소 요청 → TMS → 롯데택배 취소 → 아임웹 반영

### 흐름

```
 ┌──────────────────────────────────┐
 │ 송장 발급 전 취소                  │
 │                                  │
 │ TMS에서 주문 상태 변경             │
 │ → cancel_pending                 │
 │ → 아임웹 동기화 시 상태 보존       │
 └──────────────────────────────────┘

 ┌──────────────────────────────────┐
 │ 송장 발급 후 취소                  │
 │                                  │
 │ 1) POST /api/lotte/cancel        │
 │    → orders.status='cancel_pending'│
 │    → ALPS 집하취소 API 호출       │
 │                                  │
 │ 2) POST /api/lotte/check-cancel  │
 │    → ALPS 추적으로 취소 확인       │
 │    → CANCELLED 확인 시 DB 반영    │
 │                                  │
 │ ⚠ 배송 중 취소: ALPS 미지원       │
 │   → ALPS 웹 UI에서 수동 처리      │
 └──────────────────────────────────┘
```

## 시나리오 5: 상담 예약 관리

> 카톡/전화 상담 → GAS → TMS → 알림톡

### 흐름

```
고객이 카톡/전화로 상담 예약
        │
        ▼
 ┌──────────────────────────────────┐

 │ POST /api/consultation/sync      │
 └──────────┬───────────────────────┘
            │ Supabase consultations upsert
            ▼
 ┌──────────────────────────────────┐
 │ TMS 상담관리 (/consultations)     │
 │                                  │
 │ - 매장방문: 즉시 확정              │
 │ - 출장: 시간 제안 → 고객 선택     │
 │ - 톡상담: 시간 제한 없음           │
 │                                  │
 │ 상태 변경 시 알림톡 자동 발송       │
 │ 취소 시 GAS → 캘린더 삭제          │
 └──────────────────────────────────┘
```

## 자동채번 규칙

| 대상 | 형식 | 예시 |
|------|------|------|
| 오프라인 판매 | `OS-YYYYMMDD-NNN` | OS-20260228-001 |
| 계약서 | `CT-YYYYMMDD-NNN` | CT-20260228-001 |
| 시리얼넘버 | `MM-{SKU}-{DATE}-{SEQ}` | MM-BL7-20260228-001 |
| 송장번호 | Supabase `next_waybill()` RPC | 원자적 순번 발급 |
