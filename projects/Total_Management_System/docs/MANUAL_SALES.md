### 1초 화면 인지 (사장님 일일 동선)

```
1. /sales 진입
   → 상단 어두운 매출 카드 2개 (고객 / 거래처)
      · 이번달 큰 숫자
      · 미수금 amber (색 줄 ⚠)

2. 영역 칩 [고객(default) / 거래처 / 전체]
   → 클릭 한 번으로 영역 전환

3. 좌측 목록 — 좌측 색 줄로 1초 상태 인지:
   🟢 초록 = 판매완료 (다 끝남, 시선 안 감)
   🔴 빨강 = 미결제 (가장 시급, 청구 처리)
   🟡 노랑 = 부분결제 (선납만)
   ⚪ 회색 = 취소 (흐림 + 취소선)
   ▫️ 투명 = 진행 중 (배송/출고/결제 대기)

4. 우측 작은 도트:
   🟢 배송중 (ALPS 자동 추적, 시간 지나면 자동 초록 줄)
   🟠 출고 대기 / 결제 대기

5. 카드 클릭 → 우측 상세 패널 자동 분기
   · B2C 카드 → SaleDetailPanel (시리얼/배송 추적)
   · B2B 카드 → DeliveryDetailPanel (납품 상태/부가세/증빙)
```

### 신규 입력 진입점

| 버튼 | 라우팅 | 모드 |

## 2026-05-13 정리 — 판매 입력 "복원수리" 모드

## 2026-05-13 정리 — 판매 입력 "복원수리" 모드

`/sales/new` 상단에 모드 탭 **[제품 판매 | 복원수리]**.
- **복원수리** 탭: 좌측에 `마모루 가위`(기본 단가 1만)/`타사 가위`(기본 2만) 각각 자루 수 + 단가 입력(조정 가능). "배송비 3,000원 포함" 토글도 있음. 우측 장바구니에 "복원수리 (마모루) ×N자루" / "(타사) ×M자루" 라인 + 합계.
- 저장하면 `offline_sale_items` 에 `category='RS'` 로 들어가서 대시보드/회계의 **복원수리 매출 B채널**로 잡힘 (마모루/타사 구분 유지).
- 제품 선택 목록에서 "복원수리" 더미 제품과 "RS" 카테고리 필터 버튼은 **숨김** — 복원수리는 이 "복원수리" 모드로만 입력. (기존에 등록해둔 RS 제품 데이터는 그대로 보존, 새로 못 고를 뿐)
- B2B 거래처 복원수리는 여기 말고 **`/deliveries` "+B2B수리"** 모드 사용 (거래처별 단가 자동 채움).

## 1. 개요

판매관리는 **오프라인 판매** (매장/출장/톡상담 채널)를 TMS에서 직접 관리합니다. 온라인 주문은 주문관리에서 별도 관리.

### 2026-04-30 큰 정리 (요약)
- **후기 요청은 판매에서만**: 상담관리에서는 상담완료까지만, 후기 약속/발송은 sale 카드에서 사장님이 review_type 자유 선택 (상담/복원수리/제품구매)
- **출장/매장상담 → 판매로 처리 CTA**: 어제 만난 상담을 클릭 한 번으로 판매로 → 고객 정보 자동 prefill
- **B2B 거래처별 catalog**: 거래처마다 같은 제품을 다른 이름/가격으로 자동 적용 → 송장 출력에 박힘
- **B2B 거래/납품서**(`/deliveries`)에도 catalog 자동 입력 적용

## 3. 판매 등록

### 입력 항목

| 항목 | 필수 | 설명 |
|------|------|------|
| 고객 | ✅ | 자동완성 검색 (이름/전화번호) |
| 제품 | ✅ | 제품 선택 + 수량 (여러 개 가능) |
| 시리얼 | 선택 | 가위 제품: 준비/디스플레이 창고에서 선택 |
| 결제수단 | ✅ | 카드 / 현금 / 이체 / 복합 |
| 결제상태 | ✅ | 결제완료 / 미결제 / 부분결제 |
| 채널 | ✅ | 오프라인 / 온라인 / 톡상담 |
| 할인 | 선택 | 할인 금액 입력 |
| 메모 | 선택 | 판매 관련 메모 |

### 가격 우선순위 (074 추가)
| 우선 | 적용 가격 | 설정 위치 |
|------|----------|----------|
| **1순위** | **거래처별 납품가** (catalog.unit_price) | /거래처 → 납품품목 탭 → 항목 편집 → 납품가 입력 |
| 2순위 | 고객 유형 그룹 가격 (price_groups[customer_type]) | 설정 → 판매 관리 → 단가 그룹 |
| 3순위 | 소매가 (product.price) | 제품 등록 시 |

→ 같은 가위라도 **딜러 A는 80,000원 / 딜러 B는 75,000원 / 학교 C는 70,000원** 자유 설정 가능. 고객 선택 시 cart에 즉시 자동 적용.

### 납품명 우선순위 (073 추가)
| 우선 | 적용 이름 |
|------|----------|
| **1순위** | **거래처별 납품명** (catalog.delivery_name) — 송장에 박힘 |
| 2순위 | 고객 유형 표시명 (price_groups[customer_type].display_name) |
| 3순위 | 제품명 (product.name) |

→ "MMR-150 BL" 같은 거래처 맞춤 이름이 송장/거래명세서/준비표에 자동 출력.

### 복합 결제
카드/현금/이체 금액을 각각 입력. 합계가 결제 금액과 일치해야 등록 가능. VAT는 **카드 결제 금액**에만 적용.

### B2C vs B2B 차이
| | B2C (일반/온라인) | B2B (딜러/아카데미) |
|--|-------------------|---------------------|
| 시리얼 | 준비/디스플레이에서 선택 | 시리얼 없음 (보관창고에서 차감) |
| 가격 | 소매가 | 딜러가/아카데미가 |
| 재고 차감 | stock_quantity (시리얼 sold 처리) | stock_quantity + raw_stock |

- **070 link 정보 칩** — 출장/매장상담에서 시작된 판매면 "이 판매는 [CS-...]에서 시작됨" 클릭 → 원본 상담 이동

### 가능한 액션
| 액션 | 설명 |
|------|------|

| 판매 취소 | 확인 모달 → 시리얼 복원 + 재고 복원 + 미수금 차감 |

## 6. 후기 요청 (sale 단일 진입점, 2026-04-30)

상담관리 영역에서는 후기 요청을 받지 않습니다. 모든 후기 흐름은 **판매(sale)에서**:

### 흐름
```
sale 상세 → 리뷰 관리 카드
  ├─ 약속 ✓ 토글 (사장님이 고객한테서 약속받은 경우)
  └─ "후기 요청 보내기" 클릭 → 모달
       ├─ review_type 선택 (상담 / 복원수리 / 제품구매)
       ├─ subtype 선택 (상담은 직접방문/출장/톡상담)
       └─ 알림톡 발송
```

### 후기 작성 페이지 URL
- 자동 생성: `?type=<consult|repair|purchase>&uid=<sale_number>&name=<masked>&subtype=<...>`
- sale_number를 fallback으로 후기 페이지가 매칭 → 정상 동작

### 약속 대기 탭 (`/reviews`)
- sale + repair source만 노출 (consultation 제거됨)
- 같은 phone의 다른 source 활동 칩으로 가시화 (중복 발송 방지)

## 7. B2B 거래/납품서 작성 (`/deliveries`)

판매 입력과 별도로 B2B 거래처 납품 전용 화면. catalog 자동 입력은 **동일 동작**:
- 거래처 선택 → catalog 등록 제품 카트 추가 → 납품명/납품가 자동 적용
- 송장 / 거래명세서 / 준비표에 자동 반영

## 8. 재고 연동

```
판매 등록
  ├─ B2C (시리얼 있음)
  │   ├─ 시리얼 → status: sold, sold_via: offline
  │   ├─ previous_zone 저장 (취소 시 복원용)
  │   └─ stock_quantity -N
  │
  └─ B2B (시리얼 없음)
      ├─ stock_quantity -N
      └─ raw_stock -N (보관창고에서 차감)

판매 취소
  ├─ 시리얼 → status: in_stock, zone 복원
  ├─ stock_quantity +N
  └─ 아임웹 재고 동기화 (디스플레이 제외)
```
