# 우체국 방문접수(수거) 대행

> 계약 API는 건수 조건 미달이라 사용 불가(2026-11-10 사장님 확인) → 크롬 화면 조작으로 접수.
> 결제는 접수 시점이 아니라 **실제 수거 시 승인** → 접수 버튼까지 Claude가 진행해도 됨(사장님 합의).
> 롯데(ALPS) 수거와 별개. 롯데로 되는 건은 TMS 기존 흐름을 쓴다.

## 0. 준비 (매번 확인)
- 크롬 연결: `mcp__claude-in-chrome__*` 도구가 있어야 함. 없으면 사장님께 VS Code 입력창 `@browser` 또는 `/chrome` 연결 요청 후 멈춤.
- 크롬 프로필: 우체국 아이디·비밀번호가 **저장된 프로필에만** 확장 설치(사장님 크롬엔 구글 계정 프로필 3개). 그 프로필 창이 켜져 있어야 연결됨. 로그인 칸이 자동으로 안 채워지면 다른 프로필에 연결된 것 → 멈추고 사장님께 알림(비밀번호를 묻거나 추측 입력 금지).
- 크롬 도구 사용 전 `anthropic-skills:chrome-browser` 스킬 로드(새 탭에서 작업, 끝나면 닫기, 확인창 주의).

## 1. TMS에서 건 읽기 (조회만)
- `projects/Total_Management_System/app/.env.local` 의 서비스 키로 `repairs` 조회.
- 키: `as_id` (예: AS-20261110-1234) 또는 고객 이름 → 여러 건이면 사장님께 고르게 함.
- 쓰는 항목: `name`, `phone`, `postcode`, `address`, `address_detail`, `pickup_date`, `delivery_method`, `qty_mamoru`, `qty_other`, `memo`
- **수거 요청값은 고객이 고른 그대로 옮긴다** (사장님 지시 2026-11-10):
  - `pickup_date`(수거요청일) → 우체국 수거 희망일
  - `delivery_method`(전달방법: 문앞보관-9시 이전 / 매장카운터·직접전달-9시·10시 이후 수거요청) → 우체국 수거 방식·요청 메모 칸에 **문구 그대로**
  - 시간은 '요청'일 뿐(집배원 동선상 더 일찍 옴) — 정책 [[reference_as_pickup_time_policy]]
- 받는 분(매장): `.env.local` 의 `LOTTE_SENDER_NAME / _TEL / _ZIP / _ADDR` (롯데 접수와 같은 매장 정보)
- 값은 화면 입력에만 쓰고, 채팅엔 이름·주소 요약만.

## 2. 카드 정보 (🔒)
- 파일: `C:\마모루드라이브\ClaudeSecrets\epost-card.env` (사장님이 직접 작성. 양식은 같은 폴더)
- **결제 입력 단계에서만** 읽는다. 값을 채팅·로그·메모리·저장소·다른 파일에 **절대 옮기지 않는다**(요약에도 끝 4자리만).
- 파일이 없거나 비어 있으면 멈추고 사장님께 작성 요청. 채팅으로 카드번호를 받지 않는다.

## 3. 인터넷우체국 접수 순서
> 2026-11-10 리허설(AS-20261110-4844)로 06 결제 화면까지 확인한 순서. 화면이 바뀌면 여기부터 고친다.

### 🚨 확인창(confirm/alert) 규칙 — 반드시 먼저
- 우체국은 선택할 때마다 브라우저 확인창("선택하신 주소를 입력하시겠습니까?" 등)을 띄운다. **뜨면 크롬 조작이 통째로 멈추고 도구로 못 닫는다**(사장님이 직접 눌러야 함).
- 그래서 클릭 **전에** 해당 창에 `window.confirm=(m)=>{window.__lastConfirm=m;return true}; window.alert=(m)=>{window.__lastAlert=m}` 를 건다. 본창·각 팝업 모두. 페이지가 새로 뜨면 다시 건다.
- 팝업 안 링크 클릭은 `setTimeout(()=>a.click(),0)` 로 비동기 실행(동기 클릭은 확인창에서 스크립트가 멈춤).
- 알림 문구는 `__lastAlert` 로 읽어 결과 판단(예: "총 1건 신청목록에 추가되었습니다.").

### 팝업 다루기 (주소찾기·기존받는분·물품정보)
- 팝업은 별도 창이라 탭 도구로 안 보인다 → **버튼은 실제 마우스 클릭(computer left_click)으로 연다**(스크립트 클릭은 팝업 차단됨).
- 페이지가 뜨자마자 본창 `window.open` 을 감싸서 열리는 창을 `window.__pops[창이름]` 에 받아 둔다:
  `const o=window.open; window.open=function(...a){const w=o.apply(this,a); (window.__pops=window.__pops||{})[a[1]||'_']=w; return w}`
  - 🚫 `window.open('', 이름)` 으로 다시 찾지 말 것 — 창이 아직 없으면 **빈 창을 새로 만들어** 화면이 꼬인다(리허설 2회차 사고).
  - 주소찾기 = `list_view` / 기존받는 분 = `pop_RecSrchAddr` / 물품정보 불러오기 = `mailContPop`
  - 팝업 문서가 다 뜰 때까지 0.5초 간격으로 기다린 뒤 조작.
- '주소찾기' 버튼이 숨겨져(display:none) 있을 때가 있다 → `style.display='inline-block'` 로 보이게 한 뒤 화면 좌표로 실제 클릭.
- 실제 클릭이 꼭 필요한 것: 팝업 3개 버튼 + **모바일영수증 '미신청' 체크박스**(스크립트 클릭은 무시됨).
- 02 칸은 '다음' 누르면 잠긴다. 고치려면 '방문접수소포정보 수정' → 고침 → '방문접수소포정보 적용'(확인창 자동) → '다음'.

### ✅ 신청 전 필수 3가지 (하나라도 빠지면 '신청'이 안 됨 — 사장님 확인)
1. 맨 위 **[필수] 우편금지물품·취급제한품목 및 손해배상 안내 확인** 체크
2. 05 받는 분 목록 → **'주소검증'**
3. 06 결제수단 입력 → **'결제카드검증'**
→ 셋 다 끝난 뒤 '신청'.

### 순서
1. 로그인: `https://www.epost.go.kr/usr/login/cafzc008k01.jsp` → 아이디 로그인 탭(자동완성) → 빨간 '로그인'.
   - '비밀번호 변경' 안내가 뜨면 **누르지 말고**(확인창 뜸) 바로 다음 단계 주소로 이동.
2. 방문접수 화면: 메인 상단 '국내소포'에 마우스 올림 → '방문접수소포(픽업)' → **'방문접수소포 예약'**(반품예약 아님). 결과 주소 `parcel.epost.go.kr/general.RetrieveGeneralNewGubunLogin.parcel`.
   - 처음 뜨는 '마약류 안내' 팝업은 무시.
3. 맨 위 '[필수] 우편금지물품… 안내 확인' 체크.
4. **01 보내는 분 = 고객** (회원정보=매장이 미리 채워져 있으니 덮어쓴다)
   - 이름 `custName` ← `name`
   - 주소는 읽기전용 → '주소찾기'(실제 클릭) → `list_view` 에서 `#keyword` ← TMS `address` → `#btnImgSrch` → 결과 중 **우편번호가 TMS `postcode`와 같은** 도로명 링크(`a#hi`, 우편번호는 바로 앞 링크) 클릭 → 상세 입력:
       - TMS `address_detail` 이 **'X동 Y호' 형태**(`/(\d+)\s*동\s*(\d+)\s*호/`)이고 팝업에 '상세주소(아파트)'(`#apart_yn1`)가 있으면 → 아파트 방식: `#reg_apartdong` ← X, `#reg_apartho` ← Y (나머지 문구가 있으면 버리지 말고 보고)
       - **그 외 전부** → '상세주소'(`#apart_yn2`) 선택 후 `#reg_address2` ← `address_detail` **그대로** (사장님 지시 2026-11-10)
       - → '주소입력'. (우체국이 뒤에 "(동이름)"을 자동으로 붙임 — 정상)
     - 결과 0건/여러 건인데 우편번호 일치가 없으면 멈추고 질문.
   - 휴대전화 `cell1/cell2/cell3` ← `phone` 3분할. 이메일은 회원 이메일(매장) 그대로.
   - '다음'
5. **02 방문접수 소포정보**
   - 요금부담: '사전결제(비대면)' 기본 그대로
   - **모바일영수증: '미신청'(`#mreceipt_n`)** — 신청이면 고객 번호로 영수증 문자 감 (사장님 지시)
   - 접수결과 이메일: 수신함(매장 이메일) 그대로
   - 방문접수일자 `#labwishReceiptTime` ← `pickup_date` (목록에 없으면 멈추고 가장 빠른 날 제안). 방문신청시간은 '09:00~18:00' 하나뿐(시간 지정 불가).
   - 보관장소 `#pickupKeep` = **'05 직접입력'** → `#pickupKeepNm` ← TMS `delivery_method` **문구 그대로**
   - '다음'
6. **03 받는 분 = 매장**: '기존받는 분 정보검색'(실제 클릭) → `pop_RecSrchAddr` 에 확인창 규칙 걸고 → 첫 행 이름 '마모루미용가위' 링크 클릭(삭제 버튼 금지) → 08362 부광로 88 SKV1, B동 311호 / 010-2248-3562 채워졌는지 확인 → 아래쪽 '다음'.
7. **04 물품정보**: '물품정보 불러오기'(실제 클릭) → `mailContPop` 에서 '미용가위' 링크 클릭(수정·삭제 금지) → 미용가위 / [29]기타 / 5kg / 80cm / 세금계산서 발행요청 들어갔는지 확인. 소포개수는 비움(1개).
   - '받는 분 목록에 추가' → `__lastAlert` 가 "총 1건 신청목록에 추가되었습니다." 인지 확인.
8. **05 받는 분 목록**: 🚨 **목록은 우체국 서버에 남는다**(리허설 건이 다음 접수에 섞여 2건이 됨). '받는 분 목록에 추가' **전에** 05 목록을 열어 남은 행이 있으면 '전체삭제'로 비우고, 추가 후 **정확히 1건(받는 분=마모루미용가위)** 인지 확인. 1건이 아니면 신청 금지. → 1건 확인 → 목록 아래 빨간 **'주소검증'** 버튼 클릭(확인창 규칙 건 상태) → `__lastAlert` 문구 확인 + 목록 상태가 정상(파랑)·오류 0건인지 확인 → '다음'. **주소검증 안 하면 신청 안 됨**(사장님 확인 2026-11-10). 빨강(오류)이면 멈추고 보고.
9. **06 결제수단 등록** (카드 파일에서 이 단계에만 읽음)
   - **입력 방법 = 클립보드 붙여넣기**(카드 값이 대화에 안 남게): `scripts/card-clip.ps1 -Field <칸id>` 로 그 칸 값만 클립보드에 → 본창에서 그 칸 `focus()` → `ctrl+v` → 자릿수만 확인. 9칸 끝나면 `-Field clear` 로 클립보드 비우기. 값 직접 타이핑·출력 금지.
   - `creditNo1~4` 카드번호 4자리씩 / `creditExp1` 월 / `creditExp2` 연 / `creditPwd1`·`creditPwd2` 비밀번호 앞 2자리 각 1칸 / `creditBirth` 생년월일 6자리(`CARD_OWNER_ID`)
   - **'결제카드검증'** 먼저 → 통과 문구 확인. 실패하면 **재시도 금지**(3회 틀리면 카드 정지) → 멈추고 보고.
   - '신청' → 확인창 자동 확인 → 접수 완료 화면.
10. 접수번호(등기번호)·수거일 읽어서 보고.

## 4. 멈추고 묻는 경우 (그 외엔 끝까지 진행)
- TMS 주소와 우체국 주소 검색 결과가 다르거나 후보가 여러 개
- 수거 희망일 선택 불가(휴일·마감) → 가능한 가장 빠른 날 제안
- 같은 고객으로 이미 접수된 건이 보임(중복 접수 방지)
- 오류·확인창이 2~3회 반복
- 결제카드검증 실패 (재시도하지 말 것)
- 신청 직전 요약: 고객 이름·주소·수거일·보관장소 문구가 TMS와 다르면
