# 우체국 방문접수(수거) 대행

> 계약 API는 건수 조건 미달이라 사용 불가(2026-11-10 사장님 확인) → 크롬 화면 조작으로 접수.
> 결제는 접수 시점이 아니라 **실제 수거 시 승인** → 접수 버튼까지 Claude가 진행해도 됨(사장님 합의).
> 롯데(ALPS) 수거와 별개. 롯데로 되는 건은 TMS 기존 흐름을 쓴다.

## 0. 준비 (매번 확인)
- 크롬 연결: `mcp__claude-in-chrome__*` 도구가 있어야 함. 없으면 사장님께 VS Code 입력창 `@browser` 또는 `/chrome` 연결 요청 후 멈춤.
- 크롬 프로필: 우체국 아이디·비밀번호가 **저장된 프로필에만** 확장 설치(사장님 크롬엔 구글 계정 프로필 3개). 그 프로필 창이 켜져 있어야 연결됨. 로그인 칸이 자동으로 안 채워지면 다른 프로필에 연결된 것 → 멈추고 사장님께 알림(비밀번호를 묻거나 추측 입력 금지).
- 크롬 도구 사용 전 `anthropic-skills:chrome-browser` 스킬 로드(새 탭에서 작업, 끝나면 닫기, 확인창 주의).

## 1. TMS에서 건 읽기 (조회만)
- `projects/Total_Management_System/app/.env.local` 의 서비스 키로 `repairs` 조회.
- 키: `as_id` (예: AS-20261110-1234) 또는 고객 이름 → 여러 건이면 사장님께 고르게 함.
- 쓰는 항목: `name`, `phone`, `postcode`, `address`, `address_detail`, `pickup_date`, `qty_mamoru`, `qty_other`, `memo`
- 받는 분(매장): `.env.local` 의 `LOTTE_SENDER_NAME / _TEL / _ZIP / _ADDR` (롯데 접수와 같은 매장 정보)
- 값은 화면 입력에만 쓰고, 채팅엔 이름·주소 요약만.

## 2. 카드 정보 (🔒)
- 파일: `C:\마모루드라이브\ClaudeSecrets\epost-card.env` (사장님이 직접 작성. 양식은 같은 폴더)
- **결제 입력 단계에서만** 읽는다. 값을 채팅·로그·메모리·저장소·다른 파일에 **절대 옮기지 않는다**(요약에도 끝 4자리만).
- 파일이 없거나 비어 있으면 멈추고 사장님께 작성 요청. 채팅으로 카드번호를 받지 않는다.

## 3. 인터넷우체국 접수 순서
> ⚠️ 첫 실행 때 사장님과 함께 실제 화면 순서를 확인해 아래를 채운다(추측 금지). 화면이 바뀌면 여기부터 고친다.
1. 인터넷우체국 접속 → 로그인 상태 확인 (풀려 있으면 사장님께 로그인 요청 후 대기 — 인증은 대신 하지 않음)
2. 방문접수(소포) 메뉴: `(첫 실행 때 기록)`
3. 보내는 분 = 고객 / 받는 분 = 매장 / 수거 희망일 = `pickup_date`
4. 물품: `(첫 실행 때 기록 — 품목명·중량·크기·가액 기본값)`
5. 결제: 카드번호·유효기간·비밀번호 앞 2자리 → 접수
6. 접수번호(등기번호) 확인

## 4. 멈추고 묻는 경우 (그 외엔 끝까지 진행)
- TMS 주소와 우체국 주소 검색 결과가 다르거나 후보가 여러 개
- 수거 희망일 선택 불가(휴일·마감) → 가능한 가장 빠른 날 제안
- 같은 고객으로 이미 접수된 건이 보임(중복 접수 방지)
- 오류·확인창이 2~3회 반복

## 5. 끝나면 보고
- 접수번호, 수거 예정일, 고객 이름, 카드 끝 4자리
- TMS 기록: `(첫 실행 후 결정 — 저장할 칸 정해지면 여기 기록)`
- 만든 탭 닫기
